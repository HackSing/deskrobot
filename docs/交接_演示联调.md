## 3. 怎么跑

启动后端，终端会打印看板地址、H5 地址、推送状态：

```bash
python run_local.py
```

不用机器人、不用对方前端就能自测一遍，约一分钟：

```bash
python demo/e2e_demo.py
```

跑单元测试：

```bash
python -m pytest -q
```

手工驱动：桌面看板底部调试框，或手机 H5 加 `?debug=1`，依次输入"小登，开始会议"、"小登，资料里 A 家和 C 家的交期分别是多少"、"小登，那 B 家呢"、"小登，会议结束"。

## 4. 前端联调步骤

1. **先问清对方是哪种接法。** 接推送：他们有一个 HTTP 接收地址。拉取：他们的页面直接连我们的 `/ws` 和 `/api/state`。两种都支持，也可以同时。
2. **接推送**：在 `.env` 填 `H5_PUSH_URL`，有鉴权再填 `H5_PUSH_TOKEN`，重启后端。终端第三行会显示推送地址。对方在自己机器上跑接收端的话，地址用对方的局域网 IP。
3. **拉取**：不用配任何东西。对方页面从自己的开发服务器请求我们的接口时跨域已放开。
4. 跑 `python demo/e2e_demo.py`，或手工输入四句话，盯着对方页面看三个切换点：开始后切会中、提问后出问答、结束后切纪要。
5. 字段名对不上就改 `core/push.py` 的 `adapt()`，一处改完全局生效。对方要的字段和我们的对照，用 `docs/演示对接_mock版.md` 第 3 节的表。
6. 手机打不开我们的地址，先查三件事：是否同一个 Wi-Fi；Windows 防火墙是否放行 8766 入站；终端打印的 IP 是否是真实网卡而不是虚拟网卡。本机曾打印过 198.18.0.1 这种虚拟地址，遇到就改用 `ipconfig` 里无线网卡的 IPv4。

## 6. 关键决定和原因

- **不用智能体框架。** 问答是一个带对话历史的单次调用加 JSON 解析，没有工具循环，框架只会增加延迟和打包风险。
- **`.env` 优先于系统环境变量。** 本机用户级环境变量里有别的项目留下的 `LLM_MODEL=deepseek-ai/DeepSeek-V3.2`，原来的 setdefault 会被它盖掉，每个问题都答"没找到"。
- **deepseek-flash 必须关思考。** 不关的话推理内容把 max_tokens 吃光，正文返回空串。通过 `LLM_EXTRA={"thinking":{"type":"disabled"},"max_tokens":400}` 并进每次请求体。
- **JSON 模式下对话历史里的 assistant 内容存 JSON 原文。** 存纯文本时 DeepSeek 只回空白，追问必挂。解析出空文本还会去掉 JSON 模式重问一次。
- **LLM 看到的是完整 mock 记录，不是灌了多少。** 提问不受灌入进度限制，任何时候问都行。灌入只是让看板动起来。
- **推送为主，拉取保底。** 对方自建页面接推送最省事；`/ws` 和 `h5.html` 留着，对方没做完也能演。
