# 三人分工方案

更新日期：2026-09-19。以仓库当前 main 的代码为准。分工按三块：硬件侧、大脑、前端 H5。每个人先读 README、AGENTS.md 和 contracts.py，再读自己那一节。H5 需要的字段和接口见 `docs/接口说明.md`。

## 1. 现状盘点

已经能跑的：状态机 `core/orchestrator.py`、契约 `contracts.py`、看板接口 `web/server.py`、三套假模块 `mocks/`、本地存储 `brain/store.py`、资料提取 `brain/materials.py`、两组测试 `tests/`。`python run_local.py` 用假语音、假机器人、假大脑可以走完一整场会议。

| 模块 | 现状 | 剩余工作量 |
| --- | --- | --- |
| 语音 `speech/` | `providers.py` 里 ASR 和 TTS 两个函数直接抛 NotImplementedError，真链路整体不通；播报期间全部丢帧，没有打断 | 最重 |
| 机器人 `robot_io/` | 代码写完，从未上过真机，`real.py` 留有两处 TODO | 中，全靠真机核对 |
| 大脑 `brain/` 与状态机 `core/` | 状态机完整；真大脑是四个无记忆的单次调用，没有多轮、没有工具、没有打断处理 | 重，问答要重写 |
| 页面 `web/` | 一个 104 行的最小桌面页；没有 H5、没有扫码、没有角色；后端缺房间接口 | 重，H5 是全新功能 |

机器人名字定为"小登"。`.env` 里 `ROBOT_NAME` 要改，代码里写死的"主持人"要换成读配置，假大脑里有一处，测试里有一处。

## 2. 分工原则

- 三块按数据流切。硬件侧只碰声音和机器人本体；大脑是硬件和 H5 之间的全部逻辑，包括状态机、理解、问答、纪要、记忆，以及 H5 要调的后端接口；H5 只做页面和用户端表现。
- 目录不重叠，AGENTS.md 的规则不变：只改自己的目录，模块之间只通过 contracts.py 交互，SDK 调用包在 `asyncio.to_thread` 里，key 只放 .env。
- 假设只有一台机器人，机器人时间按第 7 节排班。
- 假模块一个都不删，任何真模块出问题用 `USE_FAKE_*` 开关一键退回。

## 3. 目录归属

| 块 | 独占目录和文件 | 需要的资源 |
| --- | --- | --- |
| 硬件侧 | `speech/` `robot_io/` `mocks/fake_speech.py` `mocks/fake_robot.py` | 机器人，云端 ASR/TTS |
| 大脑 | `core/` `brain/` `contracts.py` `main.py` `app.py` `app.json` `requirements.txt` `web/server.py` `mocks/fake_brain.py` `tests/` `demo/seed.py` | LLM key，联调时要机器人 |
| 前端 H5 | `web/static/` | 不需要机器人 |

两条边界，按下面的建议执行，有异议三人当面定：

1. **H5 的后端接口归大脑。** 房间、加入、上传、推送这些接口都依赖状态机和快照，放在大脑一侧最顺。H5 只管页面。
2. **唤醒词之后的文本由大脑切。** 硬件侧只做"听到小登"这道门，把整句原文交给大脑做意图识别。指令规则从 `speech/commands.py` 挪到 `brain/` 下，单测跟着走。这样加一种说法不用碰硬件代码。

## 4. 硬件侧：语音、动效、硬件输入输出

图上的四个场景，以及每个场景交给大脑的是什么：

| 场景 | 硬件侧做什么 | 交给大脑 |
| --- | --- | --- |
| 会议开始唤醒词"小登，开始会议" | 持续听，切句，识别成整句文本 | `on_utterance` 整句原文 |
| 会议进行中的持续录音 | 每句都切、都识别、都回调 | `on_utterance` |
| 机器人输出时被打断"小登……" | 播报中也要听；听到名字立即停播放 | 先 `on_interrupt`，再 `on_utterance` |
| 会议结束唤醒词"小登，会议结束" | 同开始 | `on_utterance` |

任务全部必做，按顺序推进。团队已有云端 ASR 和 TTS 的 API。

1. **先让机器人开口：`providers.tts`**。输出 16 位单声道 PCM，采样率 24000，单次不超过 4 MiB，长文本分段。解码用的包走大脑加依赖。失败时记日志直接返回，不要把异常抛到状态机。
2. **再让机器人听懂：`providers.asr`**。输入 16 kHz 单声道 16 位 PCM 整句，识别不出返回空字符串，单次超时不超过 5 秒。热词传机器人名字和参会人姓名，名单由大脑在开场时通过 `hotwords` 写入。
3. **切句阈值 `segmenter.py`**。音量阈值 500、静音 700 毫秒、最短 400 毫秒都是默认值，真会议室用真麦克风录三段试：安静、一个人说话、两个人交替。三个参数改成读环境变量。
4. **打断**。这是新需求。现在播报期间 `_speaking` 为真时整帧丢弃，要改成播报中仍然切句识别，识别结果里含名字就停止播放、调 `on_interrupt`、再把整句送出去；不含名字的丢弃。要防机器人听到自己：播报结束后留尾巴并重置切句缓冲，必要时比对播报文本过滤回声。
5. **真机核对反馈表 `robot_io/cues.py`**。12 个 cue 用了 10 个行为 ID：standby、listening、awake_idle、thinking、speaking、speechless、agent_question、shock、happy、sad。设备没有的 ID 会被 `_try` 静默吞掉，必须逐个触发看。同时核对侧灯和底灯的 zone 名、灯效名、三段进度色。
6. **拍背输入与跟随冲突**。确认 press 和 long_press 能到达回调，解决 `inputs.wait` 超时异常的 TODO。人脸跟随开启后点头可能被覆盖，点头前暂停跟随或去掉俯仰只留灯效。

没有机器人时：只有 `speech/real.py` 里读麦克风和放音频两处需要真机，其余用本地 wav 和本地播放器离线做。

**验收**

- 对着机器人说"小登，开始供应商报价的会议"，被识别并得到播报回应。
- 一轮问答往返不超过 5 秒。连续说 10 句，至少 8 句转写可用。
- 机器人播报中说"小登"能在 1 秒内停下来，播报中不叫名字不会误触发。
- 真机上 12 个 cue 各有可见反应，底灯三段色正确，拍背能确认待办。

## 5. 大脑

大脑是硬件和 H5 之间的全部逻辑。不用智能体框架，问答做成自己写的带记忆的工具调用循环。

### 5.1 功能清单

| # | 功能 | 现状 | 代码位置 |
| --- | --- | --- | --- |
| 1 | 会议状态机，总控 | 已有，要加打断和追问 | `core/orchestrator.py` |
| 2 | 意图识别与开场解析 | 有正则版，要加 LLM 兜底 | 规则从 `speech/commands.py` 挪到 `brain/` |
| 3 | 资料入库与检索索引 | 有提取，无索引 | `brain/materials.py` |
| 4 | 会中问答智能体，记忆、工具、联网 | 要重写 | `brain/real.py` |
| 5 | 跑题检测 | 已有，要加预筛 | `brain/real.py` |
| 6 | 计时、议程推进、超时提醒 | 已有 | `core/orchestrator.py` |
| 7 | 记重点 | 已有 | `core/orchestrator.py` |
| 8 | 纪要生成与待办确认 | 已有，要加校验和兜底 | `brain/real.py` |
| 9 | 记忆与存储 | 有两层，缺对话记忆和检索 | `brain/store.py` |
| 10 | 打断处理 | 新建 | 状态机加硬件侧契约 |
| 11 | 对外接口与快照，H5 后端 | 有基础接口，缺房间与推送 | `web/server.py` |
| 12 | LLM 客户端与评测 | 新建 | `brain/llm.py` |

### 5.2 每个功能的框架

**1 会议状态机**

- 三个状态：idle、meeting、confirming。五种事件：整句文本、指令、拍背、每秒 tick、打断。
- 结构是一张状态转移表加副作用。每个动作跑在一个可取消的 task 里，同一时刻只有一个动作在跑。
- 输入只来自硬件侧的回调。输出只有三种：反馈给机器人、播报给语音、快照给 H5。
- 规则：指令只在对应状态生效；空闲态要放行提问，用来问上次会议。
- 参数全部读 .env：跑题间隔、待办确认等待、追问窗口时长。

**2 意图识别与开场解析**

- 两层。先用正则匹配四个硬指令：开始、结束、记重点、提问，离线零延迟。叫了名字但正则没命中的，交给 LLM 输出意图和参数。
- 开场解析从"小登，开始供应商报价的会议，二十分钟，两个议题"里抽项目、时长、议题数，再按项目名模糊匹配会前准备，没有就按议题数平均分时间。
- 输入是硬件侧给的整句原文，含唤醒词。输出是统一的 Command 数据类。
- 名字用 `ROBOT_NAME` 读取，写死的"主持人"全部换掉。

**3 资料入库与检索索引**

- 流水线：文件转文本，按页或段落切块，每块带文件名和页码，随会前准备一起存。
- 检索用关键词重合计分，返回前三块，演示够用。超限先截断，之后改成让模型做摘要。
- 输入是 H5 上传的文件，输出是带索引的资料列表。
- 规则：单场总量有上限，同名文件覆盖，不做图片识别。

**4 会中问答智能体**

- 记忆三层。对话记忆按会议 ID 存消息列表，最近十轮原文，更早的压成一段摘要。会议内容和历史纪要不整段塞，通过工具按需检索。
- 四个工具：查转写、读资料、查历史、联网搜索。
- 循环：系统提示加记忆加问题，调模型；有工具调用就并行执行再回填；最多三轮，总预算八秒，超时用已有信息作答。
- 输出两句话以内，来源是列表，一次回答可能同时用到资料和联网。
- 追问窗口：答完开十五秒，窗口内不叫名字的话也算追问，遇到指令或静默关闭。
- 联网：演示用供应方内置搜索，之后换独立搜索 API 做成工具。
- 垫话：先播"我查一下"再跑循环，避免冷场。

**5 跑题检测**

- 触发条件：每 N 秒一次，只在会中，且最近 N 秒至少两句发言。
- 两级判断。先做启发式预筛，发言和议题词明显重合就不调模型。不确定才调模型，给议程、当前议题、最近发言，输出布尔值。
- 两级反馈：第一次只做表情，连续第二次才开口。
- 规则：拿不准算没跑题，模型失败也算没跑题。

**6 计时、议程推进与超时**

- 每秒 tick 算已用时、当前议题、进度比例。比例给底灯变色，议题超时播一次，总超时播一次。
- 输入是议程表和开场时间，输出是进度、超时反馈、播报。
- 规则：有动作在跑时不插播，每个提醒只说一次。

**7 记重点**

- 输入是指令参数，为空就取上一句发言。输出进 marks 列表、进快照、进纪要的重点栏。
- 反馈是点头。已完整。

**8 纪要生成与待办确认**

- 生成：输入参会人、标记的重点、资料、全场转写，输出结论、待办、未决问题、重点四组 JSON。
- 校验：待办负责人必须在参会人或转写出现的名字里，否则丢弃。JSON 解析失败重试一次，再失败用重点和正则抽的待办兜底。
- 确认：逐条播报，等拍背八秒，确认的打标记，全部走完落库。
- 落库三样：纪要 JSON、转写文本、待办表。

**9 记忆与存储**

| 层 | 存什么 | 位置 | 检索方式 |
| --- | --- | --- | --- |
| 对话记忆 | 本场问答消息列表 | 内存，散会时写到会议目录 | 直接进提示词 |
| 会议内容 | 转写、重点、资料块 | 状态机内存加会前准备文件 | 关键词计分 |
| 长期记忆 | 历史纪要、待办 | 会议目录加 sqlite | 按项目和关键词 |

- 要补三个检索函数：按项目找历史纪要、找未完成待办、按关键词找转写。

**10 打断处理**

- 与硬件侧的契约：播报中听到"小登"就停播放，先回调打断事件，再把整句作为正常文本送来。
- 大脑动作：取消当前动作的 task，包括在飞的 LLM 和工具调用；反馈回到 idle；清追问窗口；新句子走正常流程。
- 规则：打断不丢已进转写的内容。待办确认阶段被打断，是跳过当前条继续，还是整个停止确认，要定一个。

**11 对外接口与快照**

- 快照字段和接口清单见 `docs/接口说明.md`，那份文档是和 H5 的唯一契约，改字段先改文档。
- 推送方式：状态一变就通过 WebSocket 广播完整快照，H5 收到就渲染，散会后收到带纪要的快照就切纪要页。
- 房间：一次只允许一个未结束的房间；不在开放或会中状态一律拒绝加入；发起人操作校验发起人令牌。
- 状态联动：服务端订阅状态机的广播，state 变 meeting 时房间置 in_meeting，state 回 idle 且有纪要时置 ended。

**12 LLM 客户端与评测**

- 客户端只有一个 chat 函数，参数是消息、JSON 模式、工具、超时。重试一次，每次请求和响应落盘，调提示词全靠这份日志。
- 评测脚本用固定的转写和资料回放意图识别、问答、跑题、纪要四项，统计 JSON 有效率和来源正确率，不用机器人。
- 兜底：LLM key 为空自动用假大脑，假大脑和真大脑的接口保持同步。

### 5.3 节奏

- **演示前**：功能 12 的客户端、功能 2 的两层识别、功能 4 的对话记忆和追问窗口、功能 10 的打断、功能 11 的房间接口、功能 8 的校验。问答的工具先只接查转写和读资料，联网走供应方内置搜索。
- **演示后**：完整工具循环、独立搜索 API、转写摘要压缩、按句流式送 TTS、评测脚本扩展。

### 5.4 守门人

契约、入口、依赖清单、`.env.example` 只有大脑改。所有人加包都由大脑同时写进 `app.json` 和 `requirements.txt`。两次联调由大脑主持。

**验收**

- 用真大脑跑完台词四步，每个回答来源标注正确，纪要里有待办且负责人都在名单里。
- 追问"那 C 家呢"不叫名字也能接上上一问。
- 播报中被打断，1 秒内停下并正确处理新指令。
- 散会后问"上次会议定了什么"能答。
- 发起前扫码被拒，发起后能进，散会后纪要推到所有连着的手机。

## 6. 前端 H5

只做页面和用户端表现，数据全部来自 `docs/接口说明.md` 里的快照和接口。手机端 H5 为主，桌面大屏沿用现有 `index.html` 做响应式即可。

**角色**

| 角色 | 谁 | 能做什么 |
| --- | --- | --- |
| 发起人 | 会议组织者，一场只有一个 | 填会议信息、上传背景资料、发起会议、出示二维码、点开始会议、作废房间 |
| 参与人 | 扫码进来的人，可多个 | 选自己的名字加入、看会中看板、散会后收到纪要 |
| 大屏 | 会议室电脑或电视 | 只看，用现有桌面页 |

**顺序，严格按这个走**

1. 发起人打开发起页，填项目、议程、参会人、背景，点"发起会议"。
2. 发起页切换成发起人视图：二维码、已加入名单、上传资料、"开始会议"按钮。
3. 发起人上传背景资料，可多份。
4. 参与人扫码打开加入页。房间不存在或已结束就提示"会议还没发起"，不能进；房间开放或会中，显示名字选择，选完加入。
5. 发起人点"开始会议"，或有人对机器人说开会指令，所有 H5 页面切到会中看板。
6. 会议结束、待办逐条拍背确认、纪要保存后，所有连着的页面自动切到纪要视图，自己名下的待办高亮。
7. 房间结束后二维码失效，下一场重新发起。

**页面状态**，图上的三个阶段对应的视图

| 房间状态 | 状态机 | 发起人看到 | 参与人看到 |
| --- | --- | --- | --- |
| none | idle | 发起表单 | "会议还没发起" |
| open | idle | 二维码、名单、上传、开始按钮 | 加入页，加入后是等待页 |
| in_meeting | meeting | 会中看板 | 会中看板 |
| in_meeting | confirming | 会中看板，高亮正在确认的待办 | 同左 |
| ended | idle | 纪要页 | 纪要页，自己的待办高亮 |

**页面清单**，建议单独一个 `web/static/h5.html` 用 hash 路由

| 页面 | 路由 | 内容 |
| --- | --- | --- |
| 发起页 | `#host` | 表单、发起按钮；发起后变成二维码、名单、上传、开始、作废 |
| 加入页 | `#join` | 房间状态提示，名字选择，加入按钮；令牌从 URL 参数 t 读 |
| 会中看板 | `#live` | 计时、当前议题、进度条、实时转写、已记重点、最近问答，竖屏可读 |
| 纪要页 | `#minutes` | 结论、待办、未决问题、重点；自己的待办高亮，拍背确认状态可见，每条可点完成 |

**二维码**：把一个 JS 二维码库放进 `web/static/vendor/`，前端生成，不加 Python 依赖，不依赖外网。加入链接由后端返回，直接拿来生成。

**验收**

- 发起前扫码被拒，发起后扫码能进，至少两台手机同时加入。
- 发起人手机上传一份 PDF，会中提问能引用到。
- 散会后两台手机都自动跳到纪要页，各自名下的待办高亮。
- 会中看板在手机竖屏上一屏能看到计时、当前议题和最近三句转写。

## 7. 机器人排班

只有一台机器人时，机器人时间是最稀缺的资源。硬件侧几乎每一项都要真机，大脑只在联调时要。

| 时段 | 机器人归谁 | 其他人做什么 |
| --- | --- | --- |
| 第一小时 | 硬件侧核对反馈表、调 TTS 播放 | 大脑接真 LLM、搭问答循环、写房间接口；H5 搭骨架和发起页 |
| 1:00 到 1:45 | 硬件侧调 ASR、阈值、打断 | 大脑做打断处理和追问窗口；H5 做加入和会中看板 |
| 1:45 之后 | 全员联调 | |

## 9. 协作规则

在 AGENTS.md 基础上补几条。

- 只用 main，推送前 `git pull --rebase`。三人目录不重叠，冲突概率很低。
- 共享文件只有大脑改：契约、入口、依赖清单、`.env.example`、`docs/接口说明.md`。
- 每人自己的 `.env` 不提交。
- 假模块一个都不删，`USE_FAKE_*` 是演示当天的保命线。
- 联调发现的问题谁的目录谁修，跨目录的记给大脑裁决。
- 临时脚本、录音、截图不进仓库。

## 10. 风险与保底

- **语音整个不通**是最大风险。保底：看板底部的调试输入框和拍背按钮不靠麦克风也能走完整场，台词照常演。
- **打断做不完**：退回播报期间不听，靠等播完或拍背。演示台词里不安排打断。
- **云端 TTS 不通**时用免 key 的 edge-tts 做备胎，SDK 例子里有现成的。
- **行为 ID 与文档不符**不会崩，只是机器人没反应，所以硬件侧第一小时必须核对完。
- **LLM 输出不是 JSON**时用假大脑兜底，假大脑对台词四步的覆盖是够的。
- **问答循环太慢**：先播垫话；超过预算就用已检索到的内容直接答；再不行退回单次调用。
- **手机和电脑不在同一局域网**会导致二维码打不开。现场先确认所有设备连同一个 Wi-Fi，不行就开热点。
- **H5 做不完**时的最小可交付：发起页出二维码、加入页能进、会中看板能看，纪要推送退化为散会后手动刷新纪要页。
