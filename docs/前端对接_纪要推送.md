# 前端对接：会后纪要推送

更新日期：2026-09-19。前端只接一个口子：**会议结束后，后端把纪要推给页面，页面自动切到"会后确认与追踪"显示。** 其余页面（会前准备、会中主持、会中助手）保持前端自己的演示逻辑，不和后端联动。已在本机用真后端走通。

## 1. 代码在哪

| 内容 | 位置 |
| --- | --- |
| 前端源码，对方给的 meeting-host v2.0.0（React 19 + Vite 6） | `web/h5/` |
| 对接代码，全部在这一个文件 | `web/h5/src/utils/backend.js` |
| `App.jsx` 里的改动 | 搜 `connectBackend` 和 `applyMinutes`，一个订阅、一个把快照写进页面状态 |
| 构建产物，后端直接托管，手机开这个 | `web/static/h5/`，地址 `http://<后端IP>:8766/h5/` |
| 单文件保底页，原来的 h5.html | `web/static/h5.html`，地址 `/h5-lite` |
| 后端改动 | `web/server.py`：`/h5` 挂构建产物，`/h5-lite` 挂保底页；`requirements.txt` 加 `websockets` |

## 2. 接口

只用两个现有接口，不新增：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| WS | `/ws` | 连上先收一条完整快照，之后后端状态每变一次再推一条完整快照，不是增量 |
| GET | `/api/state` | 同一份快照。页面打开时先拉一次；WS 断了每 3 秒拉一次兜底，同时不断重连 |

判断"会议结束、纪要出来了"：快照里 `state` 等于 `idle` 且 `minutes` 非空。同一份纪要（`meeting_id` 加 `minutes` 内容）只应用一次，后端重启开新会后会再次应用。

页脚显示连接状态：已连接机器人后端 / 机器人后端轮询中 / 未连接机器人后端。

`.env` 里的 `H5_PUSH_URL` 这条 HTTP 推送通道这版前端用不上，因为它是纯静态页面、没有服务端可以收 POST。留着给别的接收端用，留空即可。

## 3. 字段对照

快照完整字段见 `docs/接口说明.md` 第 1 节。前端用到的：

| 快照字段 | 页面里的位置 | 说明 |
| --- | --- | --- |
| `project` | 标题 | |
| `agenda[].title` | 会议目标 / 议程 | 拼成每行"1. 标题" |
| `total` | 预计时长 | 秒换算成分钟 |
| `transcript[]` 的 `text`、`ts` | 会中助手 · 会议记录 | "张三：内容"拆成发言人和内容，`ts` 转成 HH:MM；叫机器人的指令没有发言人 |
| `minutes.highlights` | AI 会议总结、最近记录的重点 | 拼成一段话 |
| `minutes.conclusions` | 关键结论 | |
| `minutes.open_questions` | 未决问题 | 新加的卡片，为空不显示 |
| `minutes.todos[]` 的 `owner`、`content`、`due`、`confirmed` | 待办事项、下次会议追踪 | `due` 是"周五前"这种文字，输入框从日期改成了文本；`confirmed` 为真显示"已拍背确认" |

页面上写死没接后端的：参会人数"5 位"、会议日期取页面打开时间、AI 问答的关键词匹配、二维码和加入会议（存在浏览器本地，跨设备不通）。

## 4. 怎么跑

后端：

```bash
python run_local.py
```

手机和电脑连同一个 Wi-Fi，打开终端打印的 `H5：http://<IP>:8766/h5`。

不用机器人验证推送，两句话就够：

```bash
python -c "import httpx,time; c=httpx.Client(); B='http://127.0.0.1:8766'; c.post(B+'/api/debug/say',json={'text':'小登，开始会议'}); time.sleep(6); c.post(B+'/api/debug/say',json={'text':'小登，会议结束'})"
```

约 8 秒后页面应切到会后页，显示 3 条结论、3 条待办、2 条未决。整场带问答的自测用 `python demo/e2e_demo.py`。

改前端：

```bash
cd web/h5 && npm install && npm run dev
```

打开 `http://localhost:5173/h5/`，vite 把 `/api` 和 `/ws` 代理到 `127.0.0.1:8766`。后端在别的机器就 `VITE_BACKEND=http://192.168.1.8:8766 npm run dev`，或者打开页面时带参数 `?api=http://192.168.1.8:8766`。

改完构建，产物直接落到 `web/static/h5/`，连同源码一起提交，别人拉下来不用装 node 就能演：

```bash
cd web/h5 && npm run build
```

## 5. 注意

- `/ws` 依赖 `websockets` 库，之前没装，uvicorn 会悄悄拒绝所有 WebSocket 连接，桌面看板和旧 h5.html 其实也连不上。拉了新代码先 `pip install -r requirements.txt`。
- 页面打开时如果上一场已经结束，会直接显示上一场纪要。演示前重启后端就清掉了。
- 前端原型自带 localStorage 恢复提示"检测到上次未完成的会议，是否继续？"，点取消即可，不影响推送。
- 前端自己的"开始这场会议""结束会议"按钮只走前端本地演示，不会通知后端。真正的流程由机器人语音或 `/api/debug/say` 驱动。
- 待办的 `confirmed` 全是 false，因为演示跳过了拍背确认。
- 手机宽度下页面自动变单栏、隐藏侧栏，没有横向滚动，已在 375px 宽度验证。
